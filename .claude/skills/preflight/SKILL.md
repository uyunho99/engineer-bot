# 계획서 사전 검사

설계: [docs/plans/<slug>/design-doc.md](../../../docs/plans) · 결정 D1~D29

## 순서 — 이 순서를 바꾸지 마라

**1. 1단계 기계 검사**

```bash
bin/preflight "$(git branch --show-current)" --plan
```

출력 JSON 을 그대로 다음 단계의 `args` 로 쓴다. 값을 손으로 옮기지 마라.

**2. 2단계 AI 검사**

`Workflow({ scriptPath: "workflows/plan-preflight.js", args: <1단계 출력> })`

시작 전에 규모를 한 줄로 알린다. 묻는 것이 아니라 알리는 것이다.

**에이전트 총수를 미리 단정하지 마라 — 검사 단위 수보다 훨씬 크다.** 워크플로우는
4단계이고 뒤 두 단계가 *결함 수*에 비례한다:

```
검사 단위 (파일 클러스터 + 서명 후보 + 완결성 검사관 1)   ← 미리 안다
  + 발견된 결함마다 반박 검증 1
  + 살아남은 결함마다 패치 생성 1              ← 미리 알 수 없다
```

그러므로 **아는 것만 알린다:** 검사 단위 수와 동시성 캡으로 나눈 웨이브 수.
총 에이전트 수는 "단위 N개 — 결함이 나오면 그만큼 더 붙는다"로 말한다.

> 실측 (2026-09-04, 태스크 5개 플랜): 단위 **7개** → 에이전트 **39개** · 36분 ·
> 토큰 400만. 발견 18건 중 9건 생존. 단위만 세어 7개라고 예고한 것은 **5배 틀렸다.**

**결과 저장 — 세션이 한다 (AMENDMENTS B7).**

워크플로우 스크립트는 파일을 쓸 수 없다 (실측: `require` 없음, `import()` 금지).
따라서 반환값을 `docs/plans/<slug>/preflight-raw.json` 에 **세션이** 저장한다.

**손으로 옮기지 마라. 파일에서 파일로 옮겨라** — 작업 결과 파일의 `result` 키를
통째로 꺼내 쓴다. 값을 하나라도 다시 타이핑하면 하드룰 #4 위반이다.

안전망: `--record` 의 `checkPreflightRaw` 가 스키마와 `plan_sha256` 을 둘 다
검증하고, 어긋나면 `exit 4` (BLOCKED) 다. 옮기다 망가지면 조용히 통과하지 않는다.

**3. 결과 기록**

```bash
bin/preflight "$(git branch --show-current)" --record
```

종료 코드로 분기한다 — **`BLOCKED` 을 `REJECTED` 로 읽지 마라.**

| exit | 뜻 | 다음 행동 |
|---|---|---|
| `0` | `CLEAN` — 모순 없음 | 여기서 끝이다. 게이트 ① 로 넘어간다 |
| `1` | `REJECTED` — 결함을 찾았다 | 5 단계(사람 결정)로 간다 |
| `4` | **`BLOCKED` — 판정하지 못했다** | 5 단계로 가지 **마라.** 아래를 따른다 |

`exit 4` 는 검사가 "깨끗하다"도 "결함이 있다"도 말하지 못한 상태다 — 워크플로우
산출이 스키마를 어겼거나 `preflight.json` 이 손상됐거나 에이전트가 실패했다.
**결함 0건과 구분할 수 없게 보고하면 사람이 통과로 읽는다** (하드룰 #4).

이때는 사람에게 이렇게 알린다:

- `BLOCKED` 이며 **계획서의 결함이 아니라 검사 자체가 실패했다**고 말한다
- `--record` 가 출력한 `BLOCKED:` 사유를 그대로 보여준다
- 계획서를 고치라고 제안하지 마라 — 고칠 근거가 없다
- 재실행(2 단계부터)이나 원인 조사 중 무엇을 할지 물어본다


**4. 사람 결정 — 결함마다 하나씩**

`REJECTED` 면 결함마다 `AskUserQuestion` 을 **하나씩** 던진다.

- **일괄 승인을 제공하지 마라.** "전부 적용" 선택지를 만들지 마라 (설계 D13).
  결함이 많아 번거롭다면 그것은 계획서를 다시 만들라는 신호다.
- `stage: 1` 결함은 기계가 확정한 것이다. `stage: 2` 는 AI 판단이므로 오탐일 수 있다.
  사람에게 이 차이를 알려라.
- 결함의 `patch.text` 를 **그대로** 보여줘라. 다시 쓰지 마라 — 승인한 텍스트가
  그대로 들어간다 (설계 D14).

**5. 채택분 적용**

```bash
bin/preflight "$(git branch --show-current)" --apply <채택한 결함 id들>
```

종료 코드 3 은 앵커 후보가 여럿이라는 뜻이다. 후보 위치를 사람에게 보여주고 고르게 한다
(설계 D22). 첫 번째를 조용히 고르지 마라.

**6. 재검사**

적용하면 `plan.md` 해시가 바뀌므로 1단계로 돌아간다. `CLEAN` 이 나올 때까지 반복한다.

## 하지 않는 것

- `plan.md` 를 직접 편집하지 마라. `--apply` 만이 계획서를 바꾼다
- 결함을 요약해서 한꺼번에 묻지 마라 (D13)
- `preflight-raw.json` 의 값을 손으로 옮기지 마라 (하드룰 #4)
