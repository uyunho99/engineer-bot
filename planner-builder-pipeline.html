계약 스키마 체크 오버레이

기동 시 design-doc.md · plan.md의 필수 섹션을 검사. 누락이면 빌드 시작 전 REJECTED — planner 스레드로 반송.

입력: docs/plans/<branch>/ (파일이 단일 진실 — Slack으로 문서 전달 금지)

subagent-driven-development superpowers

컨트롤러는 조정만, 코딩 안 함. 태스크마다 fresh subagent를 띄우고 풀텍스트 + 누적 Discoveries를 주입한다.

태스크 루프 × N
dispatch fresh subagent→ TDD 실패 테스트 먼저 (Iron Law)→ self-review + Spec Self-Review 체크리스트→ commit
↩ self-review 실패 → 같은 subagent 수정·재검 (3회 초과 시 BLOCKED) · 별도 리뷰어 서브에이전트 없음 (v5.0.6에서 제거된 구조)
test-driven-developmentsuperpowers — deterministic 태그: red → green → refactor 강제
골든셋 검증오버레이 — generative 태그: 구조·범위·금지어 assert. 골든셋 부재 시 DONE_WITH_CONCERNS 폴백
모델 선택기계적 수정=저비용 · 멀티파일=표준 · 아키텍처/리뷰=최상위
DONE → 다음 태스크 DONE_WITH_CONCERNS → 진행+기록 NEEDS_CONTEXT → 보강 후 1회 재디스패치 BLOCKED → 사람 에스컬레이션

Project Discoveries 누적 superpowers +승격 오버레이

subagent가 발견한 함정·패턴을 discoveries.md에 쌓고, 다음 subagent마다 주입 — fresh의 맹점을 보완하는 세션 내 학습.

세션 내superpowers 원본 — 누적 → 주입
세션 종료 시오버레이 — 반복 가능 항목만 product-brain :discoveries에 draft 착지
누적 → discoveries.mddraft → product-brain :discoveries

완료 시퀀스 — PR · 프리뷰 · 보고 오버레이

전 태스크 통과 시에만 도달. PR을 만들되 머지 권한 자체가 없다. PR이 Vercel 프리뷰 배포를 트리거한다.
