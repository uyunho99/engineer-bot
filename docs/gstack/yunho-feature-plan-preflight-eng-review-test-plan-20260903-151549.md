## 검사 표면 (라우트 대신)

- `bin/preflight <branch> --gate`     형식 + 해시. 훅이 부른다. 빠르고 무료여야 한다
- `bin/preflight <branch> --plan`     짝 계산 → args JSON 을 stdout 으로
- `bin/preflight <branch> --record`   stdin 의 결과 → preflight.json + 판정
- `bin/preflight <branch> --apply …`  채택된 결함만 plan.md 에 반영
- `/preflight` 스킬                    위 네 개 + 워크플로우 + 사람 결정을 묶는다
- `bun controller/vendored.ts` 와 같은 형태의 CLI — 종료 코드가 계약이다

## 반드시 확인할 상호작용

- 결함마다 **하나씩** 채택/기각을 묻는가 (D13 — "전부 적용" 버튼이 없어야 한다)
- 채택한 것만 반영되고 기각한 것은 반영되지 않는가
- 반영된 문구가 승인한 문구와 **바이트 단위로** 같은가 (D14)
- 매치가 여럿일 때 **첫 번째를 조용히 고르지 않고** 후보를 제시하는가 (D22)
- 아무것도 채택하지 않으면 plan.md 해시가 그대로인가
- 반영 후 자동으로 재검사가 도는가 (D10 해시 변경)

## 엣지 케이스

- E1 태스크 1개 → 짝 0개, CLEAN, 던지지 않음
- E2 같은 태스크가 같은 파일 중복 기재 → 중복 제거, 자기 짝 금지
- E3 `**Files:**` 값이 비어 있음 → 빈 배열
- E4 plan.md 아직 없음 (훅 선발동) → 조용히 종료 코드 0
- E5 워크플로우 중단 → **BLOCKED** (CLEAN 아님)
- 매치 0 / 1 / 2+ 세 갈래 (D22)
- `extractFiles` 가 존재하지 않는 파일 경로를 **버리지 않는가** (D21 — 계획서의 파일은 아직 없다)

## 임계 경로 (반드시 동작해야 하는 흐름)

1. **정상 통과**: plan.md 저장 → 훅 알림 → /preflight → CLEAN → 게이트 ① 진입
2. **결함 → 수정 → 통과**: 검사 → 결함 → 하나씩 결정 → 배치 적용 → 재검사 → CLEAN
3. **거짓 통과 방지**: 검사를 안 했거나 결과가 깨졌을 때 CLEAN 이 나오지 않는가 (하드룰 #4)
4. **누락 드러내기**: 검사하지 않은 태스크가 `not_examined` 에 반드시 나타나는가 (D18)
5. **계획서 불변**: 승인 없이는 plan.md 가 어떤 경로로도 바뀌지 않는가 (하드룰 #2)

## 가장 위험한 실패

게이트 ① 에서 사람이 그것을 "통과"로 읽는다. E5 · 임계경로 3 · 4 가 이 하나를 막는다.
